Gateau Notation Sketchbook IV

The DP RX text model from docs/models/dprx.gateau, drawn under v1 rules. One layout, two modes. Every mark on the page corresponds to a line of the model, and the table at the end gives the mapping.

model: dprx.gateau (Parretto prt_dprx_top) notation: Gateau Notation v1.0 status: drawn by hand from the model

Normal mode

Four carriers, top to bottom: the message ring, the symbol stream, SDP packets and pixels. The symbol band is shaded because the link can't be stalled. State sits above as pills. The only feedback in this mode is the vblank interrupt to the policy maker.

Training mode

Same layout, same positions; only what is active changes. During training there's no main-stream content, so the tag rows, MSA, SDP and VID fade out. What remains is TRN checking patterns, SCRM descrambling for TPS4, and the message ring carrying pattern select in and status out. The loop runs through firmware: PM writes cfg_tps via a message, TRN reports matches back over the ring, and PM decides the next step.

What drawing it taught

  • The text was missing one thing the picture needed: where the edges sit. The model says "PARS latency 1" and "SCRM latency 1", but to draw the band I had to decide that both start at the same boundary. That fact is implicit in the fork. The grammar should probably state boundaries by name and attach stages to them, rather than give each stage its own latency.
  • The picture was missing one thing the text has: lock's history. In the RTL, lock passes through PARS (set from cfg.lnk_en) and is then overwritten by SCRM. Drawing it from SCRM onward is cleaner but loses that. It's a fair simplification, but the tool should say when it makes one.
  • Modes work as a pair of figures with a fixed layout. Fading rather than removing keeps every mark in the same place, so the two figures can be compared by flipping between them. A third mode would cost nothing new.
  • Long read taps are the main source of clutter. The lines from cfg and vcfg down to vmap cross every band. A layout rule could put out-of-flow state next to its heaviest reader instead of always on top, or replace long taps with a short labelled stub ("reads cfg.bpc").

Drawn by hand from docs/models/dprx.gateau, which was modelled from Parretto's source-available DisplayPort RTL. The figures model structure only, and no code is reproduced.

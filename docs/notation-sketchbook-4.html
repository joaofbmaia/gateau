Gateau Notation Sketchbook IV

The DP RX text model from docs/models/dprx.gateau, drawn under v1 rules. All four views: the bus view in two modes, the axis view, the time view, and the cost and checks overlays. Every mark corresponds to a line of the model; the table near the end gives the mapping.

model: dprx.gateau (Parretto prt_dprx_top) notation: Gateau Notation v1.1 status: drawn by hand from the model

Normal mode

Four carriers, top to bottom: the message ring, the symbol stream, SDP packets and pixels. The symbol band is shaded because the link can't be stalled. State sits above as pills. The only feedback in this mode is the vblank interrupt to the policy maker.

Training mode

Same layout, same positions; only what is active changes. During training there's no main-stream content, so the tag rows, MSA, SDP and VID fade out. What remains is TRN checking patterns, SCRM descrambling for TPS4, and the message ring carrying pattern select in and status out. The loop runs through firmware: PM writes cfg_tps via a message, TRN reports matches back over the ring, and PM decides the next step.

Axis view

Opened from the symbol band. The lane and symbol axes become wires, and the operators that act on them get NCD's glyphs. Here the bus view's Δℓ box and the VID box get their explanation.

Time view

Opened from a boundary or a join. Two are worth having for this design: the alignment TRN performs, which PARS depends on, and the join at b1.

Overlays

Overlays change what the bus view emphasises without moving anything. Two are shown here; the third (clock-domain hue) is always on.

What drawing it taught (now applied in v1.1)

  • The text was missing one thing the picture needed: where the edges sit. The model says "PARS latency 1" and "SCRM latency 1", but to draw the band I had to decide that both start at the same boundary. That fact is implicit in the fork. v1.1 now names boundaries and places stages between them (FIG D1 shows b0 and b1).
  • The picture was missing one thing the text has: lock's history. In the RTL, lock passes through PARS (set from cfg.lnk_en) and is then overwritten by SCRM. Drawing it from SCRM onward is cleaner but loses that. v1.1 adds the ≈ marker for exactly this.
  • Modes work as a pair of figures with a fixed layout. Fading rather than removing keeps every mark in the same place, so the two figures can be compared by flipping between them. A third mode would cost nothing new.
  • Long read taps are the main source of clutter. The lines from cfg and vcfg down to vmap cross every band. v1.1 turns any out-of-flow read that would cross more than one band into a stub.

Drawn by hand from docs/models/dprx.gateau, which was modelled from Parretto's source-available DisplayPort RTL. The figures model structure only, and no code is reproduced. Simplifications: PARS's write of lock, the VID vbid output, the AUX/HPD side of the PM, and MST (which this core reduces to an enable bit) are not drawn.

An invented multi-stream DisplayPort receiver, built to test the one thing v1.1 couldn't draw: items being routed apart and merged back together. It forced an eighth primitive and two new attributes, which are now v1.2.

model: docs/models/mstrx.gateau (invented, not a real design) notation: Gateau Notation v1.2 builds on: study 04 (DP RX)

The invented architecture

MSTRX takes study 04's single-stream receiver and adds multi-stream transport. The protocol ideas follow DP MST loosely: the link is divided into 64-slot MTPs, slot 0 carries the MTP header, and a payload table (vcpt) says which stream owns each slot. The policy maker rewrites the table through sideband messages, and the new table takes effect at the MTP after an ACT sequence. The hardware is mine. It has four per-stream pipelines, each a copy of study 04's PARS · MSA · SDP · VID. Video leaves as four separate outputs, but SDP packets from all four streams are merged onto one output, and each stream's MSA reports onto the shared message ring.

That gives one route and two merges, in places a real MST receiver would have them.

route ROUTE  sym → ssym[sid];  between b1 → b2
             selector  sid = vcpt.active[slot]      per symbol position s
             granularity  axis s                    # one item can feed two streams
             default   slot 0 (MTPH) and unallocated → discard
merge SDPM   sdpk[sid] → sdpo;  policy round-robin;  granularity packet;  creates sid
merge MSGM   msg from STRM[0..3] → msg;  policy ring order;  granularity message
state vcpt   out-of-flow  slot → sid
             epoch: active ← shadow at the first MTP boundary after ACT

Bus view

Indexed carriers (one per stream) are drawn as a deck: the band with two offset copies behind it, labelled ×4. ROUTE is a fan that widens from one carrier into a deck; a merge is a funnel that narrows a deck back into one carrier. The per-stream pipeline is collapsed, because study 04 already draws it.

Axis view: the slot map

The route's selector is a function of the slot index, so its axis view is the slot axis folded into rows of eight. One detail only shows up here: at two symbols per cycle, a single item can belong to two streams.

Time view: the table switch

The payload table changes while traffic flows. That's a new kind of state: double-buffered, switching at a point defined by the flow itself. v1.2 calls this an epoch, and checking it needs a time view.

What this forced into the notation (v1.2)

new primitive 8

Route and merge

A route sends each item (or part of one) to one of K carriers, chosen by a selector: a field or a state lookup. A merge combines K carriers into one under a policy. Both declare a granularity: the item size they act on, which may be finer than the carrier's item (route along an axis) or coarser (merge whole packets). Drawn as a fan and a funnel.

carrier attribute

Indexed carriers

A carrier can be replicated by an index (ssym[sid] ×4), with one copy per stream, sharing a layout. Drawn as a deck. Stages on it are replicated by the same index (×sid). Clock domains can be indexed too (vid_clk[sid]), which keeps hue meaning one thing.

state attribute

Epoch

State that is double-buffered and switches at a point defined by the flow (an MTP boundary after ACT). The model declares the switch point; the check verifies that every reader switches there.

Limits of this exercise

  • The design is invented, so the checks can only test the notation, not find real bugs. The MSGM identity failure is real within the model: I noticed it while writing MSA's emit line once per stream. I left it in on purpose, because a check that never fails shows nothing.
  • Merge fairness isn't checked yet. Round-robin over four inputs is fair, but fixed priority could starve an input. Starvation needs rates, which the model doesn't have yet. It's the obvious next attribute for merge.
  • The per-stream pipeline is drawn once and collapsed. That works because all four are identical. A design whose replicas differ (say, stream 0 with audio and the others without) would need per-index exceptions. The notation doesn't have those yet.

MSTRX is invented for this study. The MST concepts it uses (64-slot MTPs, a header in slot 0, a payload table switched by ACT) follow the DisplayPort standard loosely and are simplified; the hardware partitioning, FIFO sizes and allocation are made up. Nothing here describes a real product.
